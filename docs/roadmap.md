## P0：固定 Rust 扩展基线与首个用例

基线：财经数据 DuckDB 扩展，接口采用 `aki_stock_daily` 与 `aki_datasets()`。本阶段解决工程和来源验证，不重复选择已确认的产品或接口方向。

- [ ] 固定 Rust 工具链、Rust 扩展模板 commit、绑定和目标 DuckDB 版本（D7/D8）。
- [ ] 明确首版加载验证环境；暂不承诺独立 Rust SDK 的稳定 API 或单独分发。
- [ ] 验证东方财富候选来源，确认支持的 A 股市场及“手”到“股”的换算规则（D5）。
- [ ] 选择项目许可证，固定第一版支持的依赖版本与目标平台（D8）。

**退出条件**：工程基线、支持市场、首个来源、换算规则及目标平台明确，可以实现已采纳的 Spec。来源不适合时重评来源，接口变更须同步决策与文档。

## P1：一个数据集的可行性验证

依赖：P0。先完成固定数据下的扩展验证，将工程问题与来源问题分开定位。

- [ ] 引入并配置官方 Rust 扩展模板，完成扩展产物封装，在 DuckDB CLI 加载固定数据表函数。
- [ ] 让 `aki_stock_daily` 在 fixture 下返回固定 schema；`aki_datasets()` 无网络列出当前实现，未接通的来源不登记为已支持。
- [ ] 用 Rust 实现一个来源的最小获取与解析，核心逻辑可脱离 DuckDB 做 fixture 测试。
- [ ] 对候选来源做一次小范围真实获取，保存时间、参数、版本与字段/单位对照；fixture 的提交须先确认可再分发并清理敏感信息。
- [ ] 记录响应大小、行数、超时及重试边界，识别阻断首个用例的协议限制。

**退出条件**：Rust 扩展可加载并返回固定 schema，Rust 核心可独立测试，真实来源可获取且字段可解释。若失败先定位构建、绑定或来源问题，不开始批量接口移植。

## P2：MVP 端到端

依赖：P1。

- [ ] 连通单一来源真实数据与产品入口，保证参数和输出合同。
- [ ] 覆盖非法参数、日期边界、空结果、缺失/坏字段、前导零和重复记录。
- [ ] 覆盖遗漏/NULL/不支持的 `source`、不自动切源、成交股数换算和金额币种；目录与实际读取能力一致。
- [ ] 覆盖超时、限流或拒绝访问、结构变化、分页中断；不吞错为空表。
- [ ] 验证无网络绑定、每次扫描的请求状态、外部访问限制、FFI 错误传播及资源释放。
- [ ] 提供 SELECT、JOIN、显式建表与 Parquet 保存/重读的可运行例子。
- [ ] 验证离线发现与重复查询已物化快照无需联网，文档说明视图和 `LIMIT` 的网络行为。
- [ ] 对真实获取与离线 SQL 阶段分别记录耗时；不作无证据的性能承诺。

**退出条件**：Feature Spec 的成功标准与[接口合同](spec.md)的六项验收均有证据，所有宣称支持的版本和平台通过所需检查。

## P4：按使用需求扩展

以下为候选方向，不是已排定的承诺：

| 方向 | 启动条件 | 必须补齐 |
| --- | --- | --- |
| 前/后复权 | 首个用户确有连续价格分析需求 | 复权语义、负值/修订样例、口径区分 |
| 标的列表、ETF、指数等新数据集 | 已有具体查询场景与可用来源 | 各自 schema、代码和单位说明、离线样例 |
| 第二来源 | 有覆盖缺口或明确的可靠性需求 | 符合现有合同才能增加 `source`；无法对齐则另建数据集函数 |
| 缓存与增量更新 | 重复请求成本已被测量 | 失效、复权历史变化、原子写入及版本语义 |
| 性能优化或并发 | 瓶颈有测量证据且来源允许 | 请求预算、内存上限、取消行为和回归数据 |
| 独立 Rust SDK | Rust 调用方有实际复用需求 | 核心 API、crate 边界、稳定性及单独发布策略 |

## 需要重新决策的情况

上游失效或使用条件不适合时暂停该来源接入；Rust 模板或绑定出现阻碍时先用固定数据复现并研究替代工程方案。只有用户需求改变才重审 Rust/扩展方向。发现原讨论已有不同细节时先修文档；版本或数据口径不兼容时先更新合同与迁移说明。
