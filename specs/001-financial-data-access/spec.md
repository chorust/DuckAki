# Feature Specification: 财经数据获取与分析

**Feature Branch**: `master`（当前分支；本次未创建或切换分支）

**Created**: 2026-10-21

**Status**: Implemented and accepted on the recorded Darwin arm64 / DuckDB CLI v1.5.5 build; see [`docs/validation/acceptance.md`](../../docs/validation/acceptance.md) for scope and remaining verification limits.

**Input**: User description: "上面的spec"。指当前对话与仓库文档中已采纳的财经数据扩展方案：以 SQL 用户体验为中心，按数据集接入，来源显式选择，保留可追溯信息，让获取的数据可以直接关联、聚合和保存。

本文件是本 feature 的需求与验收基线。已确认的用户操作合同保留在[接口与数据合同](../../docs/spec.md)，工程选型保留在[技术路径](../../docs/technical-path.md)。本次整理不增加新数据集、不变更已采纳的用户操作。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 获取一个标的的可追溯历史日线 (Priority: P1)

作为本地财经数据分析用户，我希望指定股票、日期范围和实际数据来源后，直接得到可分析的历史日线，避免先编写独立抓取和清洗脚本，并能确认每条数据的来源、单位和复权口径。

**Why this priority**: 这是产品的核心价值；即使只交付一个数据集和一个来源，也应能完成真实分析所需的数据获取。

**Independent Test**: 对首版支持的一只股票和一段有已知结果的日期范围执行一次读取，逐项核对返回内容与已知记录；无需先实现目录浏览或其他数据集。

**Acceptance Scenarios**:

1. **Given** 首版支持的标的、来源及有行情的日期范围，**When** 用户显式指定三者读取日线，**Then** 返回区间内的实际交易记录，每行对应一个交易日，包含价格、量额及完整来源信息。
2. **Given** 范围两端存在交易记录且中间包含非交易日，**When** 用户读取该范围，**Then** 两端记录均包含，不生成非交易日或用前值补造行情。
3. **Given** 带市场标识且包含前导零的标的代码，**When** 用户获取数据，**Then** 返回的标的标识保留市场和前导零，不将其当成纯数字代码。
4. **Given** 来源成交量单位与标准输出不同且换算规则已经确认，**When** 用户读取记录，**Then** 成交量统一为股数，价格和成交金额可通过币种解释，首版复权口径明确为不复权。
5. **Given** 来源明确标记可选量额缺失，**When** 用户读取记录，**Then** 缺失值保持缺失，不用零冒充观测值；同批记录的获取时间一致。

### User Story 2 - 分辨无数据与读取失败 (Priority: P1)

作为分析用户，我希望能区分正常的无交易记录与参数、网络或数据质量错误，避免把抓取失败解释为市场没有交易，或把部分结果当成完整历史。

**Why this priority**: 错误的数据状态会直接影响分析结论，必须与成功读取一起交付。

**Independent Test**: 为读取入口分别提供非法输入、有效空结果及受控来源故障，核对用户看到的状态；不依赖真实来源持续在线。

**Acceptance Scenarios**:

1. **Given** 来源遗漏、为空或不受支持，标的为空或市场不受支持，日期为空、非法或倒置中的任一种情况，**When** 用户发起读取，**Then** 在访问来源前拒绝，说明错误参数及支持范围。
2. **Given** 来源明确返回合法空结果，**When** 用户读取该范围，**Then** 返回零条记录，仍可查看与非空结果一致的字段定义。
3. **Given** 超时、网络中断、限流或拒绝访问，**When** 用户读取，**Then** 在声明的等待上限内看到来源访问失败，不返回伪装成成功的空结果，也不换用其他来源。
4. **Given** 响应无法判断为空的原因、必需字段缺失、数值损坏或同批存在重复记录，**When** 用户读取，**Then** 明确报告来源数据错误，不跳过坏记录后宣称成功。
5. **Given** 多段返回尚未获取完整便中断，**When** 本次读取结束，**Then** 整次读取标为失败，不把此前取得的部分记录声明为完整结果；错误信息不包含凭据或无关敏感内容。
6. **Given** 本次读取达到声明的等待或规模上限，或用户取消读取，**When** 操作终止，**Then** 返回对应终止原因，不无限等待，也不将被截断的记录报告为成功结果。

### User Story 3 - 离线了解已支持的数据集与来源 (Priority: P2)

作为首次使用扩展的分析用户，我希望在当前分析环境中查看本版本实际支持的数据集和来源，选择可用入口，无需先联网浏览外部文档。

**Why this priority**: 明确能力范围能减少试错，也为后续逐个增加数据集提供稳定的发现方式。

**Independent Test**: 断开网络后查看能力目录，对照当前交付的读取能力核对内容，不执行任何真实行情读取。

**Acceptance Scenarios**:

1. **Given** 本版本已经交付至少一个数据集和来源组合，**When** 用户查看能力目录，**Then** 每个组合恰有一条记录，说明数据集、读取入口、实际来源和简要范围，且不发出网络请求。
2. **Given** 某些数据集仍在规划中，**When** 用户查看目录，**Then** 不显示这些未交付能力。
3. **Given** 已交付的来源当前离线，**When** 用户查看目录，**Then** 仍能了解本版本支持范围；目录不声称来源当前在线，也不执行健康探测。

### User Story 4 - 关联和聚合一次获取的结果 (Priority: P2)

作为分析用户，我希望行情能与本地自选表关联并按月份汇总；需要反复分析时，可以显式保留同一批结果，避免重复访问来源或混入新的观测批次。

**Why this priority**: 数据能在现有分析流程中直接组合，才真正消除搬运和二次清洗。

**Independent Test**: 使用一份已知行情快照和一份本地自选表，核对关联及按月、币种汇总结果；来源不可用时仍可验证本故事。

**Acceptance Scenarios**:

1. **Given** 行情记录与具有相同标的标识的本地自选表，**When** 用户关联两者，**Then** 可以取得对应名称和行情字段，无需为来源改写数据格式。
2. **Given** 已知的成交金额与币种，**When** 用户按月份及币种汇总，**Then** 汇总值与已知结果一致，缺失值按分析环境既有语义处理。
3. **Given** 用户显式保存了本次结果且随后断网，**When** 多次分析该快照，**Then** 不再访问原来源，记录及其来源、口径和获取时间保持不变。
4. **Given** 用户只发起读取但未要求保存，**When** 读取完成，**Then** 不自动创建持久结果或缓存文件。
5. **Given** 用户通过查询定义视图或限制输出行数，**When** 查阅使用说明，**Then** 能看到视图不保存远程快照、重复读取可能再次请求来源、输出行数限制不保证减少上游抓取量，以及结果排序需显式指定的约定。

---

### User Story 5 - 保存并重读可复现的分析快照 (Priority: P3)

作为需要继续分析或分享成果的用户，我希望将一次获取的结果显式保存为本地持久表或列式数据文件，并在来源变化或离线时重读原始快照。

**Why this priority**: 保存可追溯结果使一次性查询能够进入持续分析流程，但不需要额外的同步或自动缓存产品。

**Independent Test**: 将已知快照分别保存为持久表和文件，在新会话断网重读，逐项比较记录与元数据；不要求重新访问来源。

**Acceptance Scenarios**:

1. **Given** 一份完整行情快照，**When** 用户明确选择保存位置和保存操作，**Then** 可以通过分析环境已有能力保存为普通持久表或 Parquet 文件，无需专属保存接口。
2. **Given** 已保存的快照和不可用的原来源，**When** 用户在新会话重读，**Then** 标的、日期、数值、缺失值、币种、来源、复权口径及获取时间均与保存时一致。
3. **Given** 同一标的区间在后续获取时已被来源修订，**When** 用户重新读取来源，**Then** 新批次可以不同，但先前快照不会被扩展隐式覆盖或合并。

---

### Edge Cases

- **EC-001**: 日期倒置、非法、缺失，或来源、标的缺失及不支持的市场，必须在访问来源前失败；开始日等于结束日是合法单日范围。
- **EC-002**: 周末、节假日、停牌或区间外无记录，仅在来源明确返回合法无数据时返回零行；不凭含糊响应猜测“无交易”。
- **EC-003**: 上游边界规则不同或返回超出请求范围的记录，最终结果仍严格遵守两端包含的用户范围。
- **EC-004**: 来源量额缺失可保留缺失；OHLC 等必需字段损坏、非有限数值或类型无法解释必须失败，不用零掩盖。
- **EC-005**: 无法确认成交量的原始单位或股数换算，不将该来源列为标准日线的受支持来源。
- **EC-006**: 同一获取批次内，来源、标的、交易日与复权口径的组合重复，即使数值相同也作为数据质量错误，不静默去重。
- **EC-007**: 超时、限流、拒绝访问、结构变化或分段获取中断，都不得退化为成功空表、完整结果声明或自动切源。
- **EC-008**: 超过已声明的等待、响应大小或记录数量上限时失败，并说明原因；不无限重试、不返回被截断的成功结果。
- **EC-009**: 原来源离线或数据修订不改变已经保存的快照；不同获取批次的获取时间不能当作行情发生时间。
- **EC-010**: 用户未显式排序时不保证结果顺序；限制输出行数不保证限制来源请求量；视图不等于保存快照。
- **EC-011**: 后续来源口径无法满足现有合同，不能仅更换来源名称后塞入同一个数据集；需使用独立、说明差异的数据集。
- **EC-012**: 用户取消或保存失败时，不把未完成操作报告为成功，不隐式改写已有快照；具体保存覆盖行为遵循所用分析环境。
- **EC-013**: 未交付的周期、复权选项、来源或数据集不出现在可用能力与成功示例中；尝试使用未支持能力时不得隐式转成另一种查询。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 产品必须让用户在既有 SQL 分析环境直接获取财经数据，无需另写抓取、格式转换脚本或另行部署行情桥接服务。
- **FR-002**: 首版必须提供单只 A 股股票的历史日线，不复权；用户必须显式给出带市场标识的标的、开始日期、结束日期和实际来源。
- **FR-003**: 产品必须在访问来源前校验必填参数、日期与支持范围；不得猜测缺失来源、去掉代码前导零或通过模糊规则猜市场。
- **FR-004**: 产品必须对请求日期采用两端包含的范围，排除范围外记录，不生成非交易日、不填充虚构行情；单日范围合法。
- **FR-005**: 每个数据集必须具有固定、可查看的字段结构；同一数据集内更换来源不得改变用户消费这些字段的含义。
- **FR-006**: 每条日线必须包含标的、交易日期、开高低收、成交股数、成交金额、币种、实际来源、复权口径及获取时间。
- **FR-007**: 产品必须将成交量按经过确认的规则表达为股数，将价格与成交金额按明确币种的主货币单位表达，不隐式换汇；无法确认单位的来源不得进入受支持目录。
- **FR-008**: 标的、日期、开高低收、币种、来源、复权口径和获取时间必须完整；可选量额缺失必须保持缺失；非法或非有限数值必须报错。
- **FR-009**: 同一批次内，来源、标的、交易日与复权口径的组合必须唯一；全部记录必须共享本批获取时间。
- **FR-010**: 产品必须在来源明确返回合法空结果时返回零条记录，保留与非空结果一致的字段结构。
- **FR-011**: 产品必须明确区分参数错误、来源访问失败与来源数据错误；不明确的空响应、坏行、重复记录及分段获取中断均不得作为成功返回。
- **FR-012**: 产品必须仅使用用户指定的来源；指定来源失败不得自动替换为其他来源。
- **FR-013**: 产品必须为等待和可处理结果规模声明有限上限，在达到上限或用户取消时明确终止；不报告未完成的读取为成功，不无限重试，错误内容不得暴露凭据或无关敏感数据。
- **FR-014**: 用户必须能在离线状态查看当前版本已交付的数据集与来源组合，每条目录记录说明数据集名称、读取入口、来源和简要范围。
- **FR-015**: 能力目录必须与已交付的读取能力一致，不包含未来计划；目录查询不得访问网络，也不得将支持范围等同于来源实时健康状态。
- **FR-016**: 返回数据必须能够与本地表按标的关联，并直接参与按日期及币种等字段进行的聚合，无需额外来源专属清洗。
- **FR-017**: 用户必须能显式保留一次读取的快照，在断网时重复分析而不再次访问来源；读取本身不得自动创建持久表、缓存文件或覆盖既有快照。
- **FR-018**: 用户必须能使用既有保存能力将结果保存为持久表或 Parquet 文件，并在新会话离线重读，保持数值、缺失值与追溯信息不变；不要求新增专属保存入口。
- **FR-019**: 产品使用说明必须明确日期与单位合同、结果需显式排序、视图不保存快照、重复读取可能再次访问来源，以及输出行数限制不保证减少上游请求。
- **FR-020**: 新来源只有满足既有数据集的粒度、语义、单位和口径合同后才能接入同一数据集；不满足时必须分开命名并说明差异，不混合不兼容记录。
- **FR-021**: 首版必须把可发现与可读取范围限制在实际交付能力，暂不提供实时订阅、分钟或逐笔数据、复权计算、多源自动切换、指标、回测、交易执行、后台同步或自动缓存。
- **FR-022**: 产品必须提供与实际交付一致的发现、读取、关联、聚合、显式保存和重读示例，区分目标设计与已经可用的能力，避免用户将未实现功能作为可用功能。

### Key Entities *(include if feature involves data)*

- **分析用户**：使用本地分析环境查询财经数据并与自有数据组合的人；无需单独开发抓取程序。
- **数据集**：按业务内容和粒度定义的一类数据，拥有稳定字段与来源支持范围；首版是单标的、不复权历史日线。
- **数据来源**：实际提供行情的机构或站点，具有明确来源标识、覆盖范围和单位依据；提供接口参考的项目不等同于行情来源。
- **标的**：带有明确市场标识且保留原代码表达的股票；是行情与本地自选信息关联的依据。
- **日线记录**：某来源、标的、交易日和复权口径下的价格及量额观测，附有币种和本次获取时间。
- **获取批次**：同一次完整读取产生的记录集合，使用一致获取时间；必需字段损坏、重复记录或获取中断使该次读取失败。
- **能力目录项**：一个已交付数据集与来源组合的描述，帮助用户发现读取入口，不代表实时可用性承诺。
- **保存快照**：用户显式保留的某批次结果，包含原记录与追溯信息，在来源变化和离线时仍可重读。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户能够对至少 1 个受支持标的、1 个明确来源和至少 1 个完整自然年的请求区间完成读取、关联汇总、保存重读的端到端流程，需要额外编写的抓取或格式转换脚本数量为 0。
- **SC-002**: 在包含至少 2 个已知交易日、1 个非交易日及已知量额单位的受控验收样本中，预期记录、字段与换算结果 100% 相符；非交易日伪造记录、范围外记录和重复键数量均为 0。
- **SC-003**: 在常规本地验收环境中，用户断网查看首版能力目录连续 5 次，每次均在 2 秒内看到完整清单；所列组合与实际交付范围 100% 一致，网络访问次数为 0。
- **SC-004**: 参数无效、合法空结果、网络失败、限流、拒绝访问、损坏响应、重复记录和分段获取中断这 8 类验收情形全部呈现约定状态；访问来源前拒绝的非法输入、有限等待及不自动切源的行为全部符合约定。
- **SC-005**: 对一份已知快照完成一次本地信息关联和一次按月、币种汇总，结果均与预期 100% 相符；随后断网重复分析 3 次，原来源访问次数保持为 0。
- **SC-006**: 同一快照分别保存为持久表和文件，在新会话离线重读后，记录数量、价格、量额、缺失值及全部追溯信息与原快照 100% 一致；来源后续修订导致的隐式快照改写次数为 0。
- **SC-007**: 按公开示例完成一次首版支持来源的真实读取，记录来源、时间、参数和结果；至少 1 次成功读取有可追溯证据，同时说明该结果不代表长期可用性保证。

## Assumptions

- 本次需求依据用户已采纳的[接口与数据合同](../../docs/spec.md)及[讨论记录](../../docs/discussion-notes.md)，不将暂时无法加载的原助手回复作为新增事实。
- 首版只承诺一个验证通过的实际来源；东方财富是先验证的候选。其可访问性、使用条件、市场覆盖及成交量换算依据须在接入前确认；失败时重新评估来源，不静默更换来源或改变合同。
- 首版验证的是所选市场内已确认支持的股票；完整 A 股覆盖、跨市场代码映射和额外数据集不是本 feature 的默认承诺。
- 用户具备基本查询能力和可用的本地分析环境。读取真实来源依赖网络；目录发现和已保存快照的消费不依赖来源在线。
- 首版股价与金额用于数据分析，不承担结算记账的精度保证；金额与币种一起解释，不进行自动换汇。
